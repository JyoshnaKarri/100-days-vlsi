Binary Number Systems

📖 Definition
A binary number system represents numeric values using only two digits: 0 and 1. Each digit is called a bit. It is the native language of every digital circuit — every logic gate, flip‑flop, adder, and memory cell ultimately stores and processes only 0s and 1s.
📘 Concept Summary
Mastered decimal ↔ binary ↔ hexadecimal conversions, binary addition and subtraction, and 1's & 2's complement — the absolute foundation of every digital system.

Boolean Algebra & DeMorgan's Laws

📖 Definition
Boolean algebra is a branch of mathematics that works with only two values — 0 (false) and 1 (true). It defines the rules for combining these values using operators like AND (·), OR (+), and NOT ('). Every digital circuit in existence is an implementation of Boolean algebra.
📘 Concept Summary
Learned 9 Boolean laws and DeMorgan's two theorems. Applied them to simplify complex expressions step by step. Golden rule: break the line, change the sign.
🧮 The 9 Boolean Laws
LawAND FormOR Form
AnnulmentX · 0 = 0X + 1 = 1
IdentityX · 1 = XX + 0 = X
IdempotentX · X = XX + X = X
ComplementX · X' = 0X + X' = 1
Involution(X')' = X
CommutativeX · Y = Y · XX + Y = Y + X
AssociativeX·(Y·Z) = (X·Y)·ZX+(Y+Z) = (X+Y)+Z
DistributiveX·(Y+Z) = X·Y + X·ZX + (Y·Z) = (X+Y)·(X+Z)
AbsorptionX·(X+Y) = XX + (X·Y) = X
🧮 DeMorgan's Theorems
TheoremEquation
Theorem 1(X · Y)' = X' + Y'
Theorem 2(X + Y)' = X' · Y'
Golden Rule: Break the line (the NOT bar), change the sign (· becomes +, + becomes ·).
🔍 Worked Example — Simplification
Simplify: (A + B)' + A·B Step 1: Apply DeMorgan Theorem 2 to (A + B)' → A' · B' Expression now: A'·B' + A·B Step 2: This is the canonical XNOR form. Cannot be simplified further using basic laws — it is already minimal. Final: F = A'·B' + A·B (= XNOR)
DeMorgan Application — NAND from OR
Original gate: A NAND B = (A · B)' Apply DeMorgan Theorem 1: (A · B)' = A' + B' Result: A NAND B == A' OR B' So a NAND gate can be built from: • Two inverters (for A' and B') • One OR gate
💻 Verilog Code
// Day 2 — Boolean algebra is applied inside every Verilog module. // Example: NAND gate implementing (A·B)' module nand_gate ( input a, b, output y ); assign y = ~(a & b); // DeMorgan: equivalent to ~a | ~b endmodule // Testbench module nand_gate_tb; reg a, b; wire y; nand_gate uut (a, b, y); initial begin $dumpfile("nand.vcd"); $dumpvars; a=0; b=0; #10; a=0; b=1; #10; a=1; b=0; #10; a=1; b=1; #10; $finish; end endmodule
🌍 Real‑World Applications
  • Synthesis tools (Design Compiler, Yosys) use Boolean laws to minimize gate count and reduce chip area.
  • CMOS NAND/NOR mapping relies on DeMorgan to translate logic into transistor-level circuits.
  • FSM next-state logic is simplified with K‑maps and Boolean laws before being written in RTL.
  • Kernel-level optimization — every time you write assign y = ~a | ~b; you're using DeMorgan in practice.

Day 3

NAND & NOR as Universal Gates

📖 Definition
A universal gate is a gate that can implement any other logic gate (NOT, AND, OR, XOR, XNOR, etc.) using only copies of itself. The two universal gates are NAND and NOR.
📘 Concept Summary
Built NOT, AND, OR using only NAND. Built NOT, OR, AND using only NOR. Compared CMOS implementations — NAND is faster than NOR (electrons vs holes physics). Both consume 4 transistors in CMOS.
🧮 Building Gates from NAND
GateNAND Implementation
NOTNAND(A, A)
ANDNAND(NAND(A,B), NAND(A,B))
ORNAND(NAND(A,A), NAND(B,B))
🧮 Building Gates from NOR
GateNOR Implementation
NOTNOR(A, A)
ORNOR(NOR(A,B), NOR(A,B))
ANDNOR(NOR(A,A), NOR(B,B))
🔍 CMOS Implementation
GatePMOSNMOSTransistors
NAND2ParallelSeries4
NOR2SeriesParallel4
AND2NAND + Inverter—6
OR2NOR + Inverter—6
Why NAND is faster: NMOS transistors (which are in series in NOR2) have higher resistance than PMOS. Series NMOS in NOR → slower pull-down. NAND has series NMOS in the pull-down path but parallel PMOS in the pull-up — a better balance. Electrons (NMOS) are ~2–3× more mobile than holes (PMOS), so NAND > NOR.
💻 Verilog — Building AND/OR/NOT from NAND
// NAND primitive module nand2 (input a, b, output y); assign y = ~(a & b); endmodule // NOT from NAND module not_from_nand (input a, output y); nand2 u1 (a, a, y); endmodule // AND from NAND (NAND + inverter) module and_from_nand (input a, b, output y); wire n; nand2 u1 (a, b, n); nand2 u2 (n, n, y); // inverter endmodule // OR from NAND (DeMorgan) module or_from_nand (input a, b, output y); wire na, nb; nand2 u1 (a, a, na); // ~a nand2 u2 (b, b, nb); // ~b nand2 u3 (na, nb, y); // ~(~a · ~b) = a + b endmodule
🌍 Real‑World Applications
  • ASIC standard cell libraries are dominated by NAND and NOR cells because of their density and speed.
  • 7400 series ICs — the quad 2-input NAND was the first mass-produced logic chip, used in Apollo missions and early PCs.
  • NAND flash — the storage technology inside every SSD, USB drive, and phone is named after its NAND-like charge-trap structure.
  • FPGA lookup tables (LUTs) are built from small muxes, but the routing fabric is dominated by NAND-like cells.

Day 5

Carry Look‑ahead Adder (CLA)

📖 Definition
A Carry Look‑ahead Adder computes all carry bits in parallel using two signals — Generate (G) and Propagate (P). This eliminates the sequential carry chain of a ripple adder, giving constant delay regardless of bit width.
📘 Concept Summary
Learned the generate/propagate formulation, derived carry equations for all bits, and compared delay: CLA = 4 gate delays (constant) vs RCA = 2N gate delays. For 32 bits, CLA is ~16× faster.
🧮 Generate & Propagate
SignalFormulaMeaning
GiGi = Ai · BiBit generates a carry internally
PiPi = Ai ⊕ BiBit passes a carry from below
Ci+1Ci+1 = Gi + Pi·CiCarry out of bit i
🧮 4-bit CLA Carry Equations
C1 = G0 + P0·C0 C2 = G1 + P1·G0 + P1·P0·C0 C3 = G2 + P2·G1 + P2·P1·G0 + P2·P1·P0·C0 C4 = G3 + P3·G2 + P3·P2·G1 + P3·P2·P1·G0 + P3·P2·P1·P0·C0
🧮 Delay Comparison
StepGate Delays
Compute P, G1
Compute all carries2
Compute sums1
Total4 (constant)
32-bit RCA: 64 gate delays.
32-bit CLA: 4 gate delays (hierarchical, with 4-bit blocks).
Speedup: ~16× faster.
🔍 Trade‑off
CLA is faster but uses more transistors (area vs speed).
Used in high-performance CPUs (Intel, AMD, ARM).
RCA is still used in low-power, low-speed designs (watches, sensors).
💻 Verilog — 4-bit CLA
module cla4 ( input [3:0] a, b, input cin, output [3:0] sum, output cout ); wire [3:0] p, g; wire [4:0] c; assign c[0] = cin; assign p = a ^ b; // propagate assign g = a & b; // generate // Parallel carry chain assign c[1] = g[0] | (p[0] & c[0]); assign c[2] = g[1] | (p[1] & g[0]) | (p[1] & p[0] & c[0]); assign c[3] = g[2] | (p[2] & g[1]) | (p[2] & p[1] & g[0]) | (p[2] & p[1] & p[0] & c[0]); assign c[4] = g[3] | (p[3] & g[2]) | (p[3] & p[2] & g[1]) | (p[3] & p[2] & p[1] & g[0]) | (p[3] & p[2] & p[1] & p[0] & c[0]); assign sum = p ^ c[3:0]; assign cout = c[4]; endmodule
🌍 Real‑World Applications
  • ALUs in every modern processor — CLA or CLA-derived adders sit inside.
  • DSP multiply-accumulate units — the adder tree uses parallel-prefix adders derived from CLA.
  • GPU arithmetic units — high-throughput pipelines rely on short adder delays.
  • High-speed crypto accelerators — modular arithmetic needs constant-delay adders.

Day 6

Latches & Flip‑Flops — The Memory Cells of Digital Design

📖 Definition
A latch is a level-sensitive bistable circuit — its output follows the input while enabled, and holds the last value when disabled.
A flip-flop is edge-triggered — it samples its input only on a clock edge (rising or falling).
📘 Concept Summary
Learned the 4 core principles: bistability, level vs edge sensitivity, characteristic & excitation tables, and timing parameters (setup, hold, propagation delay, metastability).
🧮 The 4 Foundational Pillars
#PrincipleExplanation
1BistabilityCross-coupled gates create positive feedback; two stable states (0, 1).
2Level vs EdgeLatches are transparent when enabled. Flip-flops sample only on clock edge.
3Characteristic & ExcitationDefine Q(t+1) from Q(t) and inputs (and the inverse).
4Timing ParametersSetup, hold, propagation delay. Violations → metastability.
🧮 D Latch vs D Flip‑Flop
D Latch (level-sensitive) Enable = 1 → Q follows D (transparent) Enable = 0 → Q holds last value D Flip-Flop (edge-triggered) Rising clock edge (↑) → Q = D Otherwise → Q unchanged
💻 Verilog — D Flip‑Flop with Async Reset
module dff ( input clk, rst, d, output reg q ); always @(posedge clk or posedge rst) if (rst) q <= 1'b0; else q <= d; endmodule // Testbench module dff_tb; reg clk, rst, d; wire q; dff uut (clk, rst, d, q); always #5 clk = ~clk; initial begin $dumpfile("dff.vcd"); $dumpvars; clk=0; rst=1; d=0; #10; rst=0; d=1; #10; d=0; #10; d=1; #10; $finish; end endmodule
🌍 Real‑World Applications
  • Registers — multiple D-FFs sharing a common clock (e.g., 8-bit register in a CPU).
  • Counters — ripple counters (T-FFs), synchronous up/down counters.
  • Frequency dividers — a T-FF toggles each clock cycle, dividing frequency by 2.
  • State machines — traffic light controllers, sequence detectors.
  • Memory arrays — SRAM uses cross-coupled inverters (similar to latches) as bit cells.

Registers & Shift Registers

📖 Definition
A register is a group of D flip-flops sharing a common clock — used to store multi-bit data.
A shift register is a cascade of flip-flops where each output feeds the next input — data moves one bit per clock.

  • Digital clocks — ripple counters divide the crystal oscillator down to 1 Hz.
  • Button scanners — 74HC165 reads many switches serially.

Asynchronous FIFO — The Right Way to Cross Clock Domains

📖 Definition
An asynchronous FIFO transfers data between two clock domains using Gray-coded pointers. Because only one bit changes per count, the pointer is safe to synchronise — no metastability, no data corruption.
📘 Concept Summary
Solved the classic interview question: "How do you send data from 100 MHz to 40 MHz?" — with a Gray-coded asynchronous FIFO. Verified waveform: writes on fast clock, reads on slow clock, no glitches.
🧮 How It Works
1. Write pointer (binary) → Gray → send to read clock domain via 2-FF synchroniser 2. Read pointer (binary) → Gray → send to write clock domain via 2-FF synchroniser 3. IF/ID Pipeline Register — Fetch Meets Decode

📖 Definition
The IF/ID register is the boundary between the Fetch and Decode stages. It carries the fetched instruction and the PC+4 value. Two control cases make it interesting: stall (freeze, ignore new fetch) and flush (clear, pipeline reset).
📘 Concept Summary
Without it: Decode sits idle waiting for Fetch to finish every cycle. With it: Fetch and Decode run in parallel — instruction N decodes while instruction N+1 is already being fetched. The first real step toward 1 instruction/cycle throughput.
🧮 Waveform
Normal → instr_out = 0x00500093 stall = 1 → value holds, new fetch ignored flush = 1 → clears to 0x00000000 post-flush → resumes clean with 0x002081B3 Priority: reset > flush > stall

  • Parallelism — the entire point of pipelining is that Fetch and Decode run simultaneously.

IF/ID Register — Design Principle

📖 Definition
The principle of the IF/ID register is simple: it holds the state that the Decode stage needs — the instruction itself and the PC+4 value for later use (branch targets, jump link addresses). Understanding why it exists is as important as building it.
📘 Concept Summary
A pipeline register is a state element between two stages. Its job is to freeze the output of the previous stage so the next stage can consume it at a steady pace — decoupled from combinational delays. The IF/ID register is the first such boundary.

Without IF/IDWith IF/ID
Decode must wait for FetchDecode reads last cycle's instruction
Only 1 instruction in flightFetch and Decode overlap
Throughput = 1 / (T_fetch + T_decode)Throughput = 1 / max(T_fetch, T_decode)
No pipeline, no speedupFirst pipelining benefit
🧮 What It Carries
IF/ID payload: • instr [31:0] — the fetched instruction • pc_plus4 [31:0] — PC + 4 (for JAL link register, branch targets) Controls: • stall — hold current value (data hazard from previous stage) • flush — clear to 0 (branch mispredict, control hazard) • rst — full reset (highest priority)

  • State isolation — the pipeline register is a fundamental concept in every synchronous digital design.

  • Reusability — the same register pattern is copied for ID/EX, EX/MEM, and MEM/WB.

Day 63

ID/EX Pipeline Register — Verification

📖 Definition
The ID/EX register carries 162 bits of state from Decode to Execute: pc+4, rs1_data, rs2_data, imm, all control signals, rd, funct3, and funct7. Writing the register is easy — proving it behaves correctly under reset, stall, and flush is what matters.
📘 Concept Summary
A pipeline register that's wired correctly but never verified is a guess, not a design. All four operating modes must hold — a stale value slipping through during a stall, or a bubble that doesn't fully clear during a flush, corrupts execution silently. Day 68

Control Hazard Resolution — The Principle

📖 Definition
Control hazards arise because the pipeline has already fetched the next sequential instruction before it knows whether a branch is taken. Resolving them means either flushing wrong-path instructions (simple) or predicting the correct path (fast).
📘 Concept Summary
Three main strategies, in increasing complexity: stall (freeze fetch until branch resolves), flush (fetch speculatively, discard if wrong), predict (fetch the predicted target; only discard on mispredict). This day focused on the flush-based approach — the foundation for advanced prediction.
🧮 Three Strategies
StrategyIdeaCost
Stall until resolveFreeze IF and ID when a branch is in EX1–3 cycles lost per branch
Flush (this day)Fetch anyway, discard if branch taken1–2 cycles lost per taken branch
PredictFetch from predicted target; discard only on mispredictZero on correctly predicted branch
🧮 How Flush Resolves the Hazard
Cycle N: BEQ in EX; PC has already advanced to N+1, N+2, N+3 Cycle N: Branch taken (rs1 == rs2) → flush_if = 1, flush_id = 1 Cycle N+1: IF/ID and ID/EX registers cleared → NOPs propagate Cycle N+2: PC loaded with branch target → correct instruction fetched Result: Wrong-path instructions are discarded; program flow is correct
💻 Verilog — Flush + Priority

🌍 Real‑World Applications
  • Simple pipelines — flush-only is sufficient and used in many teaching designs.
  • Modern CPUs — build on flush with branch prediction and speculation for near-zero cost.
  • Correctness is paramount — a missing flush causes silent wrong-path execution.
  • Flush signal generation — the same logic applies to exceptions and interrupts.

📖 Definition
A direct-mapped instruction cache stores recently-fetched instructions close to the CPU. Each memory address maps to exactly one cache line (via the index bits). If the tag matches and the valid bit is set, it's a hit.

Day 76

Full Write‑Back Cache with Eviction Logic

📖 Definition
A write-back cache marks a line as dirty when written. When a line must be evicted (to make room for a new line), the dirty data is written back to memory and the dirty bit is cleared. This is the same policy used in ARM, RISC-V, and x86 CPUs.
📘 Concept Summary
Dirty bits without eviction is just bookkeeping. Eviction without writeback is just data loss. This day closes the loop — with a full writeback path in an FSM.
🧮 Waveform
Read hit → clean data Write hit → sets dirty=1 Write miss (same index, different tag) → eviction triggers writeback (mem_we=1) Eviction: addr=0x00, data=0xDEADBEEF Dirty line cleared (dirty[0]=0) New line allocated and valid (hit=1)

  • Reduces memory traffic — writes stay in cache until eviction.

Pipeline ↔ Write‑Back Cache Integration

📖 Definition
The pipeline's memory stage now talks to the write-back cache instead of talking directly to memory. The cache handles all read/write requests and manages evictions transparently. A request/ack handshake coordinates the two.
📘 Concept Summary
The pipeline no longer talks directly to memory — it talks to the cache. This reduces stalls and improves performance. This is exactly how real RISC-V cores work.
🧮 Waveform
Read hit → immediate response (ack=1) Write hit → updates cache, sets dirty Write miss → eviction triggered Eviction: addr=0x00, data=0xDEADBEEF (victim line) New line loaded → rd=0xCAFEBABE, ack=1

Store‑Data Forwarding Bug — Closing the Loop

📖 Definition
Found and fixed the bug that had been causing x2/x3/x4 to fail on Day 79: the store-data path (rs2) was never being forwarded, only the ALU's operand paths were.
